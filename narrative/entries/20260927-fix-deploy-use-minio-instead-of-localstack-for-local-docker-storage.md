## Context

`05-deployment-local-docker.md` already specified MinIO for local docker, and home-lab was already migrated to MinIO (built from source) in PR #3 after pre-built MinIO images stopped being available. The root `docker-compose.yml` was never updated in that migration, leaving local docker's own spec doc and its actual compose file contradicting each other — local docker docs said MinIO while the code still ran LocalStack.

## Decision

Apply the same decision already made for home-lab (MinIO built from source in `deploy/home-lab/minio/`) to local docker as well, reusing the same Dockerfiles rather than duplicating them, so local docker and home-lab stay in the same shape as `05-deployment-local-docker.md` requires ("Everything else... is the same shape in both"). AWS deliberately keeps the real S3 client — this decision only concerns the two Docker-based storage stand-ins.

## Consequences

`docker compose up` in local docker now builds MinIO/`mc` from source on first run (same one-time compile cost already accepted for home-lab), instead of pulling `localstack/localstack`. Local dev storage credentials changed from the LocalStack placeholder `test`/`test` to a MinIO-valid `snaglist`/`snaglist123` (MinIO requires an 8+ character root password). Nothing to do if Docker Hub/quay.io resume serving pre-built MinIO images later — the Dockerfiles can be swapped for `image:` references at that point in both places at once.
